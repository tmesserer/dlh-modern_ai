Task 0 doesn't involve training or splitting data yet — it's just instantiating the classifier correctly, so the theory you actually need is narrower than the whole project:

What you're building. DecisionTreeClassifier implements CART: it recursively splits the feature space using single-feature yes/no questions, choosing at each node the split that most reduces impurity. Since the task says Gini impurity and doesn't ask you to change criterion, you're relying on sklearn's default (criterion='gini') rather than setting it explicitly.

The three parameters you're wiring up:

min_samples_leaf — a leaf can't exist with fewer than this many samples in it. This is a light pre-pruning constraint: it stops the tree from carving out leaves so small they're basically memorizing individual points.
min_samples_split — an internal node needs at least this many samples before the algorithm will even consider splitting it further. Slightly different lever than min_samples_leaf — it acts on the parent node's size, not the resulting children's size, so the two interact but aren't redundant.
random_state — seeds sklearn's internal randomness. Worth knowing why a deterministic tree-builder needs a seed at all: when two candidate splits tie exactly on impurity decrease, sklearn breaks the tie via splitter='best' internal randomization, and feature order handling can involve randomness too. Without fixing random_state, you could theoretically get a different tree structure on two runs with identical data — which would break reproducibility for your checker.

Why no max_depth. The task explicitly says not to set one — the tree grows until every leaf is pure or one of the min_samples_* constraints stops it. That's a deliberate contrast with Task 5, where you'll later grid-search max_depth as a pre-pruning hyperparameter. Task 0 is the deliberately-unconstrained baseline you'll compare pruned versions against later.

Thought for 13s

A tree-based model is fundamentally just an automated version of "20 questions." Given a new example, the model asks a sequence of simple yes/no questions about its features — "is this wine's proline level above 755?", "is the color intensity above 3.8?" — and each answer narrows things down until it arrives at a prediction. That's it. That's the whole mechanism. No equations, no distance calculations, no linear combinations of features — just a nested set of if/else rules that the algorithm learns from data rather than a human writing them by hand.

What makes it "learned" rather than hand-coded is how those questions get chosen: at each step, the algorithm looks at every possible question it could ask and picks whichever one does the best job of separating the classes. Ask enough good questions in sequence, and you can carve up even a messy, non-linear dataset into fairly pure groups.

The catch with a single tree. If you let it keep asking questions until every group is perfectly pure, it will happily learn extremely specific, idiosyncratic rules — "if proline is between 740 and 760 AND color intensity is between 3.7 and 3.9, predict class 2" — that describe quirks of your particular training set rather than genuine patterns. That's overfitting: great performance on data it's already seen, poor performance on new data. A single tree is a fundamentally unstable, high-variance model — change the training data slightly and you can get a noticeably different tree.

The big idea that fixes this: stop trusting one tree, build many. This is the single most important conceptual leap in this whole project. Instead of one tree memorizing everything, you train a crowd of trees and combine their opinions — individual mistakes tend to cancel out, and only genuine patterns survive the averaging. There are two different philosophies for how to build that crowd:

Bagging — train many trees independently and in parallel, each on a slightly different random slice of the data, then let them vote. No tree talks to any other tree; you just average their opinions at the end. This is the idea behind Random Forest.
Boosting — train trees one at a time, in sequence, where each new tree is deliberately built to fix the mistakes the previous trees are still making. This is the idea behind AdaBoost, Gradient Boosting, and its two fast, industrial-strength descendants, XGBoost and LightGBM.

So the whole project's arc is really just three ideas stacked on top of each other: build one tree → notice it overfits, so learn to restrain it (pruning) → notice one restrained tree still isn't as strong as it could be, so learn to combine many of them (bagging and boosting).
